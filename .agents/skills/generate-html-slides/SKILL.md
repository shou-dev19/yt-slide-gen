# Generate HTML Slides Skill（図鑑見開き版）

このスキルは「格安SIM図鑑」チャンネルの**長尺動画**スライドを HTML で生成する。

## 大原則：本編スライドは全て「図鑑見開き」

本編のスライドは**例外なく** 1920×1080 の**左右2ページの本（見開き）＋机背景**で作る。
動画側（video-studio `BookSpread`）は各スライドを全画面表示するため、紙の見開きが画面いっぱいに広がり、評価パートでは ZukanSpread がその上にカメラ演出を重ねる。

唯一の例外は**冒頭の導入スライド**（速報／つかみ／タイトル／初回チャンネル誘導など、**目次より前の全スライド**）で、ここは従来の `std`（1280×720・デカ文字）で**必ず**作る（導入カットの一部だけ見開きにしない）。

> **目次は必ず見開きで作る**（`std` にしない）。`std` を許容するのは目次より前のつかみ・タイトル・初回チャンネル誘導だけで、**目次以降の全スライド**（目次・解説・比較表・評価・章扉・おすすめ診断・まとめ・過去動画CTA・定型の注意喚起/ブログ/チャンネル登録）は見開きにすること。図鑑見開きは目次から始まる。

> 旧仕様（1スライド=1280×720 のデカ文字カード）はもう使わない。評価パートだけ見開き、という中途半端な状態にしないこと。

## 0. 着手前に「直近の完成デッキ」を必ず読む

**ゼロから発明しない。** 生成に着手する前に、直近の長尺動画で完成・納品済みのスライドを読み、構成と部品の使い方をそのまま踏襲する。これを飛ばすと、過去に確立した構成（評価パートの `N-0` ペア、目次見開き、定型スライド）が毎回作り直しになり、同じ手直し指摘を繰り返すことになる。

```bash
git branch -a | grep 'video/long-'                    # 直近の長尺ブランチを確認
git show "<branch>:slides.html" | grep -n 'Slide ID'  # 構成（何を何枚で見せたか）を俯瞰
git show "<branch>:slides.html"                       # 実装を読む
```

特に次は過去デッキの構成を**そのまま踏襲**する（新解釈を持ち込まない）：

- **評価パート**：`N-0`（ロゴ＋レーダーチャート／料金プラン）＋ `N`（6観点ランク）の2見開きセット（§3）。
- **目次**：左 `.agenda`／右 `.benefits` の見開き。
- **定型スライド**：注意喚起・ブログ/note案内・チャンネル登録（§6）。

過去デッキと違う構成にする場合は、**なぜ変えたかを完了報告に明記**する。

## 1. 装丁と共有CSS

`templates/spread-base.css` に見開きの装丁と本文レイアウト部品が**全て**入っている。生成HTMLでは必ずこれをリンクし、定義済みクラスを使う（重複定義しない）。

```html
<link href="https://fonts.googleapis.com/css2?family=M+PLUS+Rounded+1c:wght@400;500;700;800;900&display=swap" rel="stylesheet">
<link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.0/css/all.min.css">
<link rel="stylesheet" href="templates/spread-base.css">
```

各見開きスライドの骨格（`--brand` 系はブランド色の上書き）:

```html
<!-- Slide ID: N -->
<div class="slide-container" style="--brand:#1565C0;--brand-deep:#0d47a1;--brand-soft:#e3f0fb">
  <div class="book">
    <div class="spine"></div>
    <div class="page left">
      <div class="page-head">左ページの見出し</div>
      <div class="page-body center"> … </div>
      <span class="page-no">― 11 ―</span>
    </div>
    <div class="page right">
      <span class="index-tab">格安SIM図鑑</span>
      <div class="page-head">右ページの見出し</div>
      <div class="page-body center"> … </div>
      <span class="page-no">― 12 ―</span>
    </div>
  </div>
</div>
```

- `.index-tab` は**右ページのみ**に置く（図鑑インデックスタブ）。右ページの `.page-head` はタブを避けるよう自動で右側に余白が入る（`spread-base.css` 側で対応済み）。
- `.page-no` はノンブル。解説・評価などの本文ページに付け、左右で連番（章扉/章カード/CTA/定型などの「扉・特殊ページ」は省略してよい）。
- **本（見開き）はほぼ全画面で表示され、スライドのコンテンツは各ページの上部 約80% に描画される。ページ下部 約20% は空白の紙面として残り、その上に video-studio の字幕が重なる**（`spread-base.css` の `.page` の `padding-bottom` で担保。per-slide で本やページの寸法を変えない）。本文がこの字幕帯に被らないよう、コンテンツは上部80%だけに収める。
- 各ページの内容領域は約 **810×772px**。`.page-body` は既定で余白を `space-evenly` に散らして縦を使い切る。単一ブロック（lead/emph 一個など）は `.center` で縦中央寄せにする。

### ブランド色（per-slide で上書き）

`--brand` / `--brand-deep` / `--brand-soft` をキャリア・章ごとに設定する。

| 対象 | brand | brand-deep | brand-soft |
|---|---|---|---|
| ドコモ系 / 赤系（ahamo・楽天・一般章） | `#C8102E` | `#9a0c23` | `#fde3e7` |
| IIJmio・青系 | `#1565C0` | `#0d47a1` | `#e3f0fb` |
| 緑系（mineo 等） | `#22a73f` | `#1c8b34` | `#e8f5e6` |

1枚の見開き内でページごとに別ブランド色にしたい場合は、その**ブロック要素に `style="--brand:…;--brand-deep:…;--brand-soft:…"` を再指定**すれば局所的に切り替わる（例：左ページ=赤、右ページ=青の比較）。

## 2. 共通レイアウト部品（spread-base.css 由来）

ページ本文はこれらの部品を組み合わせて作る。per-slide の微調整は `style` 属性で。

> **料金表記コンプライアンス（アクセストレード要請）**: 「※表示している料金はすべて月額・税込みの価格です」の注記は `spread-base.css` の `.slide-container.price-note::after` で用意済み。**料金を表示するスライドだけ**、その `<div class="slide-container ...">` に `price-note` クラスを足すと注記が下部中央に出る（オプトイン。例: `<div class="slide-container price-note" style="--brand:…">`）。料金を出さないスライドには付けない。CSS は spread-base.css 側にあるので per-slide で再定義しないこと。

| クラス | 用途 |
|---|---|
| `.page-head`（`<small>` で副題） | ページ見出し（ブランド色の下線） |
| `.page-body` / `.page-body.center` | 本文コンテナ（縦に使い切る／縦中央寄せ） |
| `.lead`（`.em` で強調） | 紙のテロップ風リード文 |
| `.rows > li`（`.ic` / `.badge` / `.tx`、`.tx .sub` / `.tx .em`） | アイコン or 番号付きリスト行 |
| `.emph`（`.big` / `.em`） | 数値・結論の強調ボックス |
| `.warn`（`.ic` / `.em`） | 注意ボックス |
| `.note` | 小さなグレーの注記 |
| `.sheet`（`th`/`td`、`.em` / `.sub`） | 紙の表（料金・比較） |
| `.big-title`（`.em`） | ページ中央の大見出し（章タイトル・CTA等） |
| `.divider`（`.kicker` / `.num` / `.seal`） | 章扉のエンブレム |
| `.visual > img` | サムネ等のビジュアルを1ページに大きく |
| `.bigicon` | 中央の大アイコン（FontAwesome） |
| `.logos > img` | ロゴ並べ |
| `.agenda` / `.benefits` | 目次／「この動画でわかること」 |
| `.head-left`/`.total`/`.head-right`/`.cards`/`.card`/`.card .rank`/`.card-name`/`.card .line`（`.line.pro`/`.line.con` の `.tag`） | 評価 Layout B（1社1見開き） |
| `.rank.SS`/`.S`/`.A`/`.B`/`.C` | 評価ランクバッジ（色は段階固定） |

### コンテンツ種別 → レイアウト指針

- **目次**：左 `.agenda`（動画の流れ）／右 `.benefits`（この動画でわかること）。
- **解説（リスト系）**：`.page-head` + `.rows`。項目が多ければ左右ページに分割（見出しに `<small>①②</small>` 等で続きを示す）。
- **数値・結論**：`.emph`。補足は隣ページに `.lead` / `.note`。
- **通信速度の実測値（1社）**：速度レポート見開き（§3.5、`shared/minsoku_speeds.json` 連携）。
- **料金・比較表**：`.sheet`。列・行が多ければ左右ページに分割。
- **注意点**：`.warn` ＋ `.note`、または左ページに `.bigicon`（⚠）。
- **イラスト/図解**：片ページを `.visual` にして大きく、もう片方で要点を `.lead`。
- **おすすめ診断・まとめ**：`.rows`（番号バッジ）や `.emph` を左右に。

## 3. 評価見開き（1社1見開き）— 必須ルール

各キャリアの評価は**1社につき1見開き**で表現する（Layout B）。台本の「スライドに表示する内容」書式：

```
評価見開き／社名／総合:rank／観点:rank(＋pro／－con) を6観点
```

- ランクは原則 `shared/sim_evaluations.json` から取り、プラス点・マイナス点は**台本のテロップ文字列（`評価見開き／…（＋pro／－con）`）をそのまま使う**（台本側で根拠照合済みのため、スライド生成時に書き換えない）。`sim_evaluations.json` 未登録のキャリアは台本側のランク・所感を使う。
- **6観点固定順**：データ料金・通信品質・初期費用・通話料・店舗サポート・オプション。
- **左ページ**：`.head-left`（ロゴ＋`.total`総合評価）／`.cards` に観点3枚（`.card` = `.rank` + `.card-name` + `.line.pro` + `.line.con`）。
  - **レーダーチャートを表示するスライドでは、画面左上（`.head-left`）に必ず各社のロゴ画像（`<img class="logo" src="public/images/logo/..." alt="...">`）を表示する。社名テキストの `.file-no` バッジ（楕円）による代用は不可。** ロゴと社名の二重表示を避け、ロゴに統一すること。料金プラン見開き `N-0`・評価見開き `N` の両方でこのルールを適用する。
- **右ページ**：`.index-tab` ＋ `.cards` に残り観点3枚。
- **レーダーチャートは `N-0` 側だけに置き、`N` の右ページには重複表示しない。** `N` の `.head-right` にミニチャートを入れると、縮小されて動画では判読不能になるうえ `.cards` の縦を圧迫して本文フォントを縮めることになる（§10 のフォント下限違反の主因）。空いた縦幅は本文サイズの確保に使う。
- ランクの色は `.rank.SS/S/A/B/C` に従う（独自配色にしない）。pro は `＋`、con は `－`。評価バッジを別途並べない。
- **免責注記（必須）**：右ページの `.cards` の直後・`.page-no` の直前に `.note` で評価の前提を必ず明記する（省略不可）：
  ```html
  <div class="note" style="font-size:28px;text-align:center;">※本評価は当チャンネルの独断と偏見による独自評価であり、キャンペーン割引等は考慮していません</div>
  ```
  `.note` の既定サイズ（44px）は `.cards` を圧迫するため、上記のように `font-size:28px` へ縮小して使う（**注記だけは 30px 下限の例外**。本文テキストは §10 の下限を守ること）。右ページに1回だけ入れれば足りる（左右両方に重複表示しない）。

> **キャリアの評価は `N-0` と `N` の2見開きセットで必ず作る（統合・省略は不可）。** `N-0` はレーダーチャート＋料金プラン、`N` は6観点ランク詳細とする。「本編では単一 `N` で自己完結させてよい」という例外は**廃止した**（この逃げ道があるせいで `N-0` が毎回省略され、レーダーチャートと料金プランが動画から落ちる事故が繰り返された）。台本のスライドID列に `N-0` があるのに作らなければ §10.1 のID一致チェックで落ちる。

### 評価見開き `N` には「料金プラン見開き `N-0`」をセットで前に置く（必須）

各キャリアの評価見開き `N`（Layout B）を作るときは、**その直前に料金プラン紹介の見開き `N-0` を必ずペアで作成する**（評価 `N` を単独で出さない）。`N-0` は「左＝ロゴ＋レーダーチャート／右＝料金プラン」の構成にする。

- **左ページ**：`.head-left`（ロゴ＋`.file-no` に社名）＋ `.visual`（`flex:1`）にレーダーチャート（`public/images/charts/<社名>.png`）を大きく表示。
- **右ページ**：`.index-tab` ＋ `.page-head`「<社名>の料金プラン」＋ 料金プラン。料金プランは次のどちらかで作る：
  - **スクショ優先**：`public/images/temp/<carrier>/` に料金表のスクショがあればそれを使う。複数プラン（例：mineo のマイピタ＋マイそく）は `.page-body.center` 内に**縦並び**で重ね、各画像の上に小見出し（`font-weight:900; color:var(--brand-deep)`）を付ける。各 `img` は `max-height` で1枚あたりの高さを抑えて2枚が収まるようにする。見出しと被らないよう `.page-body` に `margin-top` を足してもよい。
  - **スクショが無ければ `.sheet` で表組み**（`shared/sim_plans.json` 等の料金で作る）。
- `.page-no` は評価見開き `N` と連番になるように `N-0` 側を先に振る。
- ⚠ 注意：このペアの `N-0` は**章扉 `N-0`（§4）とは別物**。章扉は章カード `N`（章番号）に対する扉、こちらは評価見開き `N`（社名）に対する料金プラン導入。同一デッキ内で `N` の値が衝突しないので混同しないこと。

## 3.5 速度レポート見開き（通信速度の実測データ・みんそく連携）

台本の「スライドに表示する内容」書式：

```
速度レポート見開き／社名
```

- この書式の行は**必ず**本節のレイアウトで作る。**明示書式が無くても、スライドの主題が「特定1社の通信速度・実測値・時間帯別速度」なら本節のレイアウトで作る**（速度が6観点評価の1項目として触れられるだけの場合は適用しない）。
- **数値は `shared/minsoku_speeds.json`（親リポジトリ `../../shared/`、週次自動更新）を正とする**。台本の数値と食い違う場合は JSON を採用し、完了報告で差異を報告する。
  - 社名は `categories.mvno` / `categories.carrier` 両方の `services[].name` から探す（表記ゆれは吸収する。例: ワイモバイル→`Y!mobile`、UQモバイル→`UQ mobile`）。
  - 「楽天モバイル」は**両カテゴリに存在する**（格安SIMランキング側=`楽天モバイル`、キャリアランキング側=`楽天モバイル(キャリア)`）。台本の文脈（格安SIM比較かキャリア比較か）で選び、迷ったらキャリア側を使う。
  - 該当社が無い／JSONが読めない場合は、台本記載の数値で通常の見開き（`.emph`＋`.sheet`）を作り、**完了報告に「みんそくデータ未使用: ○○」と明記**する（JSONに無い数値をみんそく実測値として捏造しない）。
  - JSON の `fetchedAt` が生成時点より14日以上古い場合は生成を続行し、完了報告で「速度データが古い（取得日: …）。`node scripts/fetch-minsoku-speeds.js` での更新を推奨」と警告する。

レイアウト（テンプレは `slides-spread-templates.html` の「速度レポート見開き」を参照）：

- **左ページ**：`.head-left` にロゴ画像（`public/images/logo/`。社名テキストの代用不可）＋`.page-head`「○○の通信速度」→ `.page-body.center` に `.emph`「格安SIM ○社中 <span class="big">○位</span>」（カテゴリ名・母数・順位は JSON から）→ `.emph` で平均ダウンロード速度をデカ数字（`.big`）→ `.note` で平均アップロード・平均Ping。
- **右ページ**：`.index-tab`＋`.page-head`「時間帯別の平均速度 <small>直近3ヶ月</small>」→ `.sheet` で5行表（時間帯／下り／上り。Ping は表に入れず左ページの平均のみ）→ 注目ポイント一言（`.lead` または `.warn`。例「お昼でも100Mbps超え」「平日昼は大きく低速化」。**数値と矛盾する文言は不可**）→ `.note` に `※直近3ヶ月の平均｜出典: みんなのネット回線速度(みんそく)｜取得日: YYYY/M/D`（取得日は JSON の `fetchedDateJa`。**出典と取得日は省略不可**）。
- ブランド色（`--brand` 系）は該当社に合わせて per-slide 指定。ノンブル・字幕帯（下20%）回避・オーバーフロー自己点検・レンダリング自己点検ループは他の見開きと同様。

## 4. 章の入口は「章扉 N-0」1枚のみ — 章カード N は作らない

章の入口スライドは**章扉 `N-0` の1枚だけ**にする。かつての「章扉 `N-0` ＋ 章カード `N`」の2枚構成は、内容がほぼ同じスライドが連続して冗長なため**廃止**（章カードは作らない）。

- **章扉 `N-0`（にぎやか・扉ページ）**：左ページに `.divider`（`CHAPTER`/大きな番号/`FILE No.0X` シール）、右ページに `.big-title`（章テーマ）＋丸いリード。`.page-no` は付けない。
  - **キャラクター画像はスライドに焼き込まない**。本編では video-studio 側がショウ／モモコを画面隅にライブ合成するため、見開きにも描くと二重になる。扉は番号エンブレムと大見出しで魅せる。

> **台本ID振り直しルール（必須・音声/スライド同期を保つ）**：台本に章カード相当のプレーン番号 `N` のナレーション行がある場合、スライドを作らない代わりに**台本 CSV の該当行のスライドID列を振り直す**：
> - `N` の行が章の導入ナレーションのみ → `N`→`N-0`（章扉を表示したまま話す）。
> - `N` の行に「解説本文」のナレーションが含まれる → 解説スライド `N-1` を作り、`N`→`N-1` に振り直す。
> - 振り直した ID の一覧（旧→新）を完了報告に必ず含めること。

## 5. 過去動画 CTA 見開き

- 片ページを `.visual` にして `public/images/thumbnails/` の**実サムネイル**を大きく置く（汎用アイコンで代用しない。社名/トピックで部分一致選択）。
- もう片方に `.bigicon`（▶）＋ `.big-title`（「○○の解説動画もチェック！」）＋ `.note`。

## 6. 定型スライド（注意喚起／ブログ／チャンネル登録）も見開きで

旧 `public/images/slides/*.png` の貼り付けは使わない。次の内容を見開きで作る：

- **投稿時点の注意喚起**：左 `.bigicon`（ℹ）＋`.big-title`「ご注意」／右 `.warn`「料金・プラン・キャンペーンは投稿時点の情報」＋`.note`「最新は各社公式で確認」。
- **ブログ／note案内**：左 `.bigicon`（ペン）＋`.big-title`／右はページ上段に `public/images/common/ブログ_ヘッダー画像_スライド用.png`（`max-height:320px` 程度・角丸＋ドロップシャドウ）を置き、その下に `.lead`＋`.note`。**画像は `width:100%; height:auto`（または `object-fit:contain`）でアスペクト比を必ず維持**する（width/height 両方を固定して縦横比を潰さない）。
- **チャンネル登録・高評価（最終スライド）**：左 `.bigicon`（ベル）＋`.big-title`「チャンネル登録<br>よろしくお願いします！」／右 `.logos`（👍🔔）＋`.lead`。**「ご視聴いただきありがとうございました！」等の視聴者への感謝の言葉を必ず目立つ位置に入れる**こと。

## 7. 冒頭つかみスライド（std を許容する唯一の例外）— 最もリッチに作る

目次より前の導入カット（速報・タイトル・初回チャンネル誘導）だけ `std`（1280×720）でよい。最小限の `std` CSS を `<style>` にインラインし、`<div class="slide-container std" …>` で作る。

**導入スライドは視聴者の離脱を防ぐ最重要ポイント。デッキ内で最もリッチに、雑誌の表紙のような密度で作ること。** テロップ1行だけの薄いスライドは**禁止**。

**主役はフックとなるテキスト。いらすとやは余白を埋めるための脇役。** 大見出し（フック文）は 68px 以上のデカ文字＋キーワードの赤強調で最も目立たせ、いらすとや画像を添える場合はテキストより小さく（高さ 300px 程度）配置する。イラストが見出しより大きい・目立つ構図は不合格。

> **テキストで埋まっているスライドにいらすとやを無理に置かない（必須）。** 見出し・キッカー・チップ等でスライドがすでに埋まっているなら、イラストは**入れないのが正解**。空きが無いところへ `position:absolute` で敷くと、テキストの下に潜って**大半が隠れた切れ端**だけが見え（過去に導入スライド1・2で「イラストが完全に隠れている」指摘を受けた）、見た目のノイズにしかならない。判断基準は次の通り：
> - イラストを置く空きが**イラスト1枚を8割以上見せられる大きさ**（高さ 250px 程度）で確保できないなら置かない。テキストを削ってまでイラストの場所を作る必要はない。
> - 台本に「（イラスト：…）」指示があってもこれは同じ。指示があるのにテキストで埋まっていて置き場が無い場合は**イラストを省き、完了報告にその旨を書く**（無理に重ねて隠すより省くほうが良い）。
> - `opacity` を下げて背景として敷くのも不可（低品質に見える）。にぎやかさは集中線・バッジ・ロゴ・オービット等の装飾部品で出す。

- **いらすとやをグリッドの1列として置かない**：`grid-template-columns` の片方をイラストに割り当てると、テキスト列が狭まって**文字が小さくなり左に寄る**（この構図で繰り返し指摘を受けている）。イラストは `position:absolute` で右下に置き、`z-index:0` でテキストの下に敷く。テキスト（`.std-copy`）は**全幅を使って中央寄せ**にする。
- **導入スライドの文字サイズ下限**（1280×720 基準。スマホ視聴で潰れないこと）：バッジ 44px 以上／キッカー 48px 以上／大見出し 86px 以上／価格などの強調数字 42px 以上。
- **社名はテキストで小さく置かず、ロゴ画像（`public/images/logo/`）で見せる**。比較フローを作る場合は「ロゴ＋価格」を縦に積んだ組を `vs` で並べる（`display:flex`）。固定カラム数の `grid` は項目数が合わないと折り返して区切り文字が宙に浮くので使わない。

次の部品を組み合わせて情報量とインパクトを出す：

- **速報/日付バッジ**（回転させた赤帯・`box-shadow` 付き）＋**巨大な数字の強調**（例: `4,950円` を 120px 超・赤で）
- **集中線/サンバースト背景**（`repeating-conic-gradient` を薄く重ねる）や角の三角アクセント
- **キャリアロゴ**（白カード載せ）＋関連する**いらすとや画像**（驚き・悲鳴などの感情イラスト）
- 値上げ・比較モノは **Before→After の価格フロー**（旧価格に取り消し線 → 新価格をデカ文字）
- **台本の「（イラスト：…）」指示は、置き場がある場合に反映する**：台本の「スライドに表示する内容」に `（イラスト：書類に埋もれるショウ）` のようなイラスト指示があれば、その内容に最も近い `public/images/irasutoya/`（または `common/`）の画像を選んで大きく配置する。ただし上記の通り、**テキストで埋まっていて8割以上見せられる空きが無いならイラストは省く**（隠れたイラストを置くくらいなら無いほうが良い）。指示が無い場合も同じ判断でよく、イラスト無しでも上記部品（集中線・バッジ・ロゴ・巨大数字）で表紙級のリッチさは作れる。

```css
.slide-container.std { width:1280px;height:720px;border:10px solid var(--primary-color);background:white;box-sizing:border-box;position:relative;overflow:hidden;display:flex;flex-direction:column;justify-content:center;align-items:center;padding:40px;flex-shrink:0; }
body { --primary-color:#C8102E; --accent-red:#E53935; --text-dark:#212121; }
.terop-box { background:rgba(255,255,255,.9); border-left:16px solid var(--primary-color); padding:16px 32px; font-size:58px; font-weight:900; color:var(--text-dark); text-align:center; line-height:1.4; box-shadow:0 10px 20px rgba(0,0,0,.1); }
```

## 8. 文字組み・改行

- **基本は自動折り返しに任せる**。`spread-base.css` が本文クラス（`.line` / `.rows .tx`・`.sub` / `.lead` / `.warn` / `.note` / `.emph` / `.page-head small` / `.card-name` / 目次行 / `.sheet`）に `word-break: auto-phrase`（文節＝意味の切れ目で折る）＋ `text-wrap: balance`（行長を均す）を効かせている。これらのクラスでは助詞の後で割る・各行の長さを揃える作業は CSS が肩代わりするので、**先回りして手 `<br>` を入れない**。
- **手 `<br>` は最後の微調整だけ**：自動折り返しでも崩れる箇所（固有語の途中で割れる、数字と単位が分かれる、意図と違う行数になる）に限ってピンポイントで足す。判断は §10 のレンダリング自己点検で実物を見てから行う（脳内で予測して大量に入れない）。
- 数字と単位、「ホッピング」のような鉤括弧の固有語は `white-space: nowrap` で割らない。
- **端数文字の改行は厳禁**：見出し・タイトルで最終行が1〜3文字だけになる折り返し（例:「料金プ / ラン」「〜しづらくなっ / た」「速 / 度目安」）を残さない。**必ず日本語として意味の切れ目（文節）で折る**（例:「UQ mobile公式の<br>速度目安」）。折れない場合は文字サイズを下げて1行に収める。
- **キャリア/サービス名は省略しない**：✅`ソフトバンク`/`楽天モバイル`/`ドコモ`。❌`SB`/`楽天`(単体)。
- **`.note` に主要情報を入れない**：`.note` は出典・補足専用。スマホ視聴者に読ませたい本文・結論は `.lead` / `.emph` / `.rows` に置く（例:「100Mbpsは実はかなり余裕のある数字」は `.note` ではなく `.lead` 級）。

## 9. 画像アセット

- **プレースホルダ禁止**。`public/images/` から文脈に最適な既存画像を選ぶ（`GEMINI.md` に一覧）。
- 選択優先度：`temp/<carrier>/`（キャンペーンバナー等の直接的画像） > `charts/`（レーダーチャート） > `thumbnails/`（過去動画CTA） > `logo/` > `irasutoya/`（状況イラスト） > `common/`（概念図）。
- **FontAwesome のアイコン名は Free 版に存在するものだけ使う**。未定義のクラスを書いてもエラーは出ず、`::before` の content が空になって**アイコンだけが黙って消える**。要素は幅0になるだけでレイアウトも崩れない。`-low` / `-simple-low` のような階調バリエーションや業種系アイコンは **Pro 限定**のことが多い（実際に `fa-gauge-simple-low` が Free に無く、Slide 4-1 のアイコンが1つだけ欠けた）。
  - **キャプチャ時に機械判定される**（§10 のレンダリング自己点検ループ 3.）。`⚠️ 表示されていない FontAwesome アイコン` が出たら、スライドID・DOMパス・クラス名が示されるので差し替える。実在する近縁アイコンは次で探す：
    ```bash
    curl -s https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.0/css/all.min.css | grep -o '\.fa-<語幹>[a-z0-9-]*:before' | sort -u
    ```
  - キャプチャ前に確認したい場合は、使用アイコンと CSS の定義済みクラスを突き合わせて**出力が空**であることを見る：
    ```bash
    curl -s https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.0/css/all.min.css > /tmp/fa.css
    comm -13 <(grep -o '\.fa-[a-z0-9-]*:before' /tmp/fa.css | sed 's/^\.//;s/:before$//' | sort -u) \
             <(grep -o 'fa-\(solid\|regular\|brands\) fa-[a-z0-9-]*' slides.html | sed 's/.* //' | sort -u)
    ```
- **ファイル名は実在ファイルと厳密一致させる**（`ls` で確認）。特にレーダーチャートは `public/images/charts/<正式社名>.png` で、社名の綴り・スペース・記号まで一致が必要（実在例: `UQ mobile.png`／`Y!mobile.png`／`楽天モバイル.png`／`日本通信SIM.png`／`povo2.0.png`）。`UQ.png` のような略称パスは**リンク切れ**になる。過去動画CTAサムネは `thumbnails/` の実ファイル名に動画タイトルで部分一致させる。
- **いらすとやは余白埋めの最終手段（使いすぎ厳禁）**：本編でいらすとやを使ってよいのは、台本の情報をすべて載せてもなお余白が大きいページだけ（§10 の優先順位に従う）。**スライドに載せるべきテキストで埋まっているページには、いらすとやを入れない**（余白が無いのに置くと他要素の下に潜って隠れる）。イラストは「余白があるから足す」ものであって、必ず入れる部品ではない。**片ページ丸ごと汎用イラストだけの構成は禁止**。目安：1見開きに1枚まで・同一画像はデッキ全体で2回まで。使う場合は文脈に合う画像を選ぶ（例: 迷う/多すぎ→`pose_atama_kakaeru_woman.png`、損/手数料→`seikyuusyo_shock.png`、店舗→`kaden_tenin16_woman_ojigi.png`、自宅ネット→`internet_modem_router.png` 等。ジェネレータで作る場合は「キーワード→ファイル名」の対応表を持たせると安定する）。
- **外部出典の明記（必須）**：第三者サイトから取得した画像には取得元を正確に併記（例 `出典：Amazon.co.jp（IIJmio商品ページ）`。Amazon が権利者ではない点に注意）。キャプションは `.note` 相当の小さめ・グレーで画像直下に。

## 10. 自己チェック（重要）

### 10.1 スライドIDの完全一致（最優先・機械チェック）

**台本のスライドID列の集合と、HTML の `<!-- Slide ID: XX -->` の集合を完全一致させる。** 過不足はどちらも事故になる：

- **台本にあるのに作っていない** → そのIDのナレーション中に前のスライドが出たままになる（`N-0` の料金プラン・レーダーチャートが動画から丸ごと落ちる事故はこれ）。
- **台本に無いのに作った** → 一生表示されない孤児スライドになる。

`generate-scenario` が `セリフ台本.txt` の各行の slideId を `slide_NN.png` に **1:1 で対応**させて表示するため、ここがズレると音声とスライドが同期しない。

**照合先は台本のマスターCSV**（`packages/scenario-gen/archive/videos/<NN_タイトル>/<long|short>/<タイトル>.csv`）。`packages/slide-gen/台本.txt` は `bridge.sh a` が撒いた**コピーなので古いことがある**（マスター側でIDを振り直しても、再コピーしない限り古いIDのまま残る）。台本.txt を使うなら先に `bash scripts/bridge.sh <master.csv> a` で撒き直すこと。

生成後、**差分ゼロを確認してから完了とする**（`$MASTER` にマスターCSVのパスを入れる）:

```bash
diff <(awk -F',' 'NR>1{print $(NF-1)}' "$MASTER" | sed 's/"//g' | awk '!seen[$0]++') \
     <(grep -o 'Slide ID: [0-9-]*' slides.html | sed 's/Slide ID: //')
```

差分が出た場合は、**HTML 側を台本に合わせる**のが原則（台本は scenario-gen が正）。台本側の採番が明らかに誤っている場合のみ §4 の振り直しルールを適用し、旧→新の一覧を完了報告に必ず含める。

### 10.2 レイアウトの判断基準（HTML を書く段階で守る）

- **フォント下限**：見開きの本文テキストは **`font-size` 30px 以上・`font-weight` 700 以上**（1920×1080 基準。`.note` の注記だけ 28px まで可）。`spread-base.css` の既定値を per-slide の `style`／`<style>` オーバーライドで 30px 未満に縮めるのは**禁止**（過去に `.card .line` を 23px まで落として「文字が細くて読めない」指摘を受けた）。**入り切らない場合はフォントを縮めるのではなく、文言を短く要約して収める。**
- **`spread-base.css` の既定より小さいインライン指定を書かない**：`.rows .tx`（既定48px）や `.emph`（既定52px）に `style="font-size:38px"` のような縮小指定を付けない。**カード・ボックスの内側に余白が余っているのは「文字が小さすぎる」サイン**であり、枠を余らせたまま小さい文字を置くのは不合格（「ブロック内に余白が多くてもったいない」という指摘を繰り返し受けている）。カード内の文字は 46px 以上を目安に、2行に折り返してでも大きくする。
- **内容量が一定でないカードを `flex:1 1 0` で引き伸ばさない**：引き伸ばすと1行のカードは内側が死に余白になり、3行になったカードは逆に枠から溢れる（`overflow:visible` なので機械判定の「見切れ」にも掛からず見逃しやすい）。`flex:0 0 auto` で内容ぴったりの高さにして、余りは親の `justify-content:space-evenly` に散らすこと。
- **オーバーフロー厳禁**：各ページ（約810×772px）に全要素が収まること。はみ出すなら行数削減／文言短縮／隣ページへ分割（フォント縮小は上の下限まで）。本の下端より下（画面下部約20%）は字幕帯なので、ここに本文を置かない。
- **余白を残さない**：文字・アイコン・画像は大きめに。`.page-body`（既定 `space-evenly`）とフォント/行間で縦を使い切る。1ページ1〜3要素のような薄い内容でも、大きな文字・大アイコン・大ビジュアルでスカスカに見せない（目安：本文の文字は 40px 以上、見出し 56〜60px、章タイトル・CTA は 90px 以上）。詰めすぎてもいけない。
  - **ページの1/3以上が空白なら不合格**とみなし、次の**優先順位**で必ず埋める：**①台本の該当スライドID行（セリフと「スライドに表示する内容」列）を読み直し、視聴者へ視覚的に伝えるべき不足内容（分岐条件・注意点・価格・補足）があればテキスト・表・部品として追記** ②文字・アイコンの拡大 ③隣ページとの内容再配分 ④それでも埋まらない時のみ、文脈に合う**いらすとや画像**（`public/images/irasutoya/`）を差し込む（§9 の上限内で）。定型スライド（注意喚起・ブログ・チャンネル登録）も同様。
- 評価見開きの `.cards` は左右3枚ずつが基本。card 内のテキストが長い時は `.line` を短く要約。

### レンダリング自己点検ループ（必須・手直しを減らす要）

脳内チェックだけで終わらせず、**実際にレンダリングした PNG を必ず目視して直す**。これがユーザー手直しを減らす最重要工程。

1. **§10.1 のスライドID差分チェックを実行し、差分ゼロにする。** ここがズレたままキャプチャしても意味がないので必ず最初に潰す。
2. `npm run capture-slides-html` でキャプチャする（§11）。
3. **実行ログの機械判定を先に潰す**。キャプチャは DOM を計測して次の3点を確定的に判定し、該当があれば警告を出す（詳細は `out/slide_whitespace-report.json` と `out/slide_layout-report.json`）。目視より確実なので、警告が消えるまで直してから 3. へ進む。
   - `下端の空きが 1/3 以上のページ` … §10 の余白規則。
   - `いらすとやが主役になっているページ` … §7・§9。ページ内容に占めるイラスト面積がテキスト面積を上回るか、ページの4割以上を占めると不合格。
   - `他要素に隠れているいらすとや画像` … §7・§9。上と**逆向き**の失敗（イラストがテキストの下に潜っている）。絵のある画素のうち8割以上が見えていないと不合格。**位置をずらして見せるのではなく、テキストで埋まっているならイラストごと削除する**のが原則。
   - `テキストが見切れている箇所` / `内容領域からはみ出している箇所` … §10.2 のオーバーフロー規則。前者はブラウザが実際に文字を切っている箇所、後者は字幕帯（下部の紙面）への侵入を含む。
   - `表示されていない FontAwesome アイコン` … §9 のアイコン規則。Free に無い名前や綴り間違いを検出する（スライドID・ページ・DOMパス・クラス名が出る）。
4. 出力された各 PNG を **画像として読み込んで実物を確認**する（Read で画像を開く、または Playwright MCP でスクショ）。全スライドを見る。機械判定で潰せない次の観点に集中する：
   - **文字が細い・小さい**：スマホの小さい画面でも読めるか。§10.2 のフォント下限（30px / weight 700）を下回っている箇所が無いか。
   - **不自然な折り返し**：固有語の途中で割れていないか、数字と単位が分かれていないか、行数が意図とズレていないか（自動折り返しで大半は解消するはず。残った崩れだけ §8 の手 `<br>` か `white-space:nowrap` で直す）。
   - **詰めすぎ**：窮屈になっていないか（スカスカ側は 2. の余白判定が見る）。
   - **台本カバレッジ**：台本の該当行にある伝えるべき情報（分岐条件・注意点・価格など）がスライドに載っているか（§9・§10 の優先順位で直す）。イラストの大きさそのものは 2. が見るが、**イラストが文脈に合っているか**は目視でしか分からない。
   - **いらすとやの見え方**：隠れ（可視率）そのものは 3. の機械判定が見るので、目視では「絵が小さすぎて何のイラストか分からない」「見切れて不自然な位置で切れている」といった、比率では表せない見え方を確認する。直し方は隠れと同じで、**位置を動かして見せるのではなくイラストを削除する**（§7・§9）。テキストが主役なので、削っても情報は落ちない。
   - **アセット**：ロゴ・チャート・スクショが正しく表示され、欠けていないか。
5. 問題があれば HTML を修正 → **再キャプチャして再確認**。崩れが無くなるまで繰り返す。
6. 修正がゼロになって初めて完了とする。手直し候補をユーザーに丸投げしない。

## 11. 出力フォーマット

- 全スライドを1つのHTMLファイルに `div` で縦に並べる（`body` レイアウトは `spread-base.css` が担う）。
- 各スライドの直前に `<!-- Slide ID: XX -->` を置き、台本の行IDと対応付ける（`N-0`/`N-1`/`N-2` などのサフィックスも可）。
- 出力後、`npm run capture-slides-html` でキャプチャされ、見開きは 1920×1080、冒頭 std は 1280×720 の PNG になる。**キャプチャ後は §10 のレンダリング自己点検ループを必ず実行**してから完了とする。
